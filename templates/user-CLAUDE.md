# How to work with me

These are my personal preferences. They apply in every project.

## Language
- Talk to me in **German**. Keep code, file names and identifiers in English unless I say otherwise.
- Keep answers short. Explain more only when I ask or when it matters for a decision.

## Who I am
- I'm a creator, not a programmer: level design, 3D modeling and photogrammetry, sound design and music.
  My big project is a Portal 2 mod that I'm moving to Strata Source (Portal 2: Community Edition).
- When you write code or scripts, tell me in plain words what they do, where they live and how to run them again.
  Avoid jargon. If you have to use a technical term, explain it once.

## My creative work stays mine
- Do not make creative decisions on your own: level and puzzle design, art direction, lighting mood,
  sound design and music. Offer options, explain trade-offs, and let me choose.
- Never compose or generate music for me. Help with tools, technique, theory and production questions when I ask.
- Go ahead and automate tedious pipeline work (converting, renaming, packing, generating config files, batch jobs)
  once we've agreed on what it should do.

## Safety
- Before changing files in a project, check that it is under version control or backed up. If it isn't, say so
  and suggest `/version-control` first.
- Never delete files, overwrite my work or run destructive git commands (reset --hard, push --force, clean)
  without asking me first and explaining what would be lost.
- Raw photogrammetry data (photos, scan projects, dense meshes) does not belong in git.

## Source engine / Strata facts
- Source and especially Strata Source details are obscure and change between versions. Don't guess.
  Check the files on disk first (FGD files, existing VMF/VMT/QC files, gameinfo.txt, compile logs), then the
  Valve Developer Community wiki or the Strata Source wiki. Tell me when you're not sure.
- Never invent entity names, keyvalues, inputs/outputs or shader parameters.
- You can't see Hammer or play the game. When something has to be tested, tell me exactly what to compile or
  try, and ask me for the result or the log.

## Getting better over time
- When we figure out something about a project that you'll need again, offer to add it to that project's CLAUDE.md.
- When I repeat a task, offer to turn it into a skill.
